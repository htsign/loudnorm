# loudnorm — フォルダ一括の音量そろえ

フォルダ（サブフォルダ以下すべて）の曲のラウドネス（EBU R128 / ITU-R BS.1770 の積分ラウドネス）を測り、
**目標から許容幅を超えてずれた曲だけ** を補正します。許容幅に収まる曲には一切手を加えません。

目標は次から選べます。上部のグラフをクリックするか数値を入力すると「カスタム」になります。

| 目標 | 内容 |
|---|---|
| 中央値（既定） | 外れ値に強い代表値 |
| 平均値 | LUFS の算術平均 |
| トリム平均 | 小さい側・大きい側それぞれ 10% を除いた平均 |
| 変更が最少になる値 | 許容幅に収まる曲が最も多くなる値（同数なら中央値に近いもの） |
| カスタム | 任意の値 |

グラフは「分布（各曲）」と「ヒストグラム」を切り替えられ、下に箱ひげ（Q1・中央値・Q3、◆は平均）を表示します。

対応形式: MP3 / FLAC / M4A（AAC・ALAC）/ Ogg Vorbis / Opus / WAV

## ビルド（Windows）

```
cargo build --release
```

`target\release\loudnorm.exe` ができます。MSVC ツールチェーン（Visual Studio Build Tools）が必要です。

## 実行に必要なもの

- **ffmpeg と ffprobe**（再エンコードと、Opus など一部形式の解析に使用）
  - PATH 上、exe と同じフォルダ、または画面上で指定した場所から探します。
  - MP3 の再エンコードには libmp3lame、Vorbis には libvorbis を含むビルドが必要です（起動時に検出し、ない場合はその形式だけ失敗します）。
- 解析は MP3・FLAC・AAC-LC・ALAC・Vorbis・WAV なら ffmpeg なしでも動きます（Opus と HE-AAC は ffmpeg が必要）。ffmpeg なしで適用できるのは「無劣化を優先」の MP3 と「ReplayGain タグだけ」です。

## 使い方

1. 「選択…」でフォルダを選ぶ（exe にフォルダをドロップして起動しても可）。自動で解析します。
2. 中央値・分布・各曲の補正量を確認する。**この時点ではファイルは変更されません。**
3. 方法・許容幅・出力先を決めて「N 曲に適用…」→「実行」。
4. 結果を確かめるときは再解析してください（適用後は二重適用を防ぐため、再解析するまで適用できません）。

## 速度

解析も適用も曲単位で並列に処理します（既定は CPU の論理コア数 − 1、画面の「同時に処理する曲数」で変更可）。
「真のピークを測る」をオフにするとサンプルピークで代用し、解析が速くなります（ピーク制限の判定は甘くなります）。

## 設定ファイル

画面の設定（ffmpeg の場所、方法、許容幅、ピーク上限、再エンコード設定、並列数、真のピーク、出力、更新日時の保持、最後に解析したフォルダ、ウィンドウの大きさと最大化、一覧の列幅）は、変更するたびに INI ファイルへ保存され、次回起動時に読み込まれます。

- 既定の場所: `%APPDATA%\loudnorm\settings.ini`
- exe と同じフォルダに `settings.ini` を置くと、そちらを使います（持ち運び用）。
- 手で編集しても構いません。読めない値は既定値に戻し、ログに表示します。

## 調整方法

| 方法 | 内容 | タグ |
|---|---|---|
| 再エンコード（既定） | ずれた曲を 0.01 dB 精度で補正して再エンコード。MP3 は LAME（CBR 320 / 256 / VBR V0 から選択）、FLAC・ALAC・WAV は元のビット深度のまま可逆、AAC は元のビットレート以上、Vorbis は品質指定 | 元ファイルから引き継ぐ |
| 無劣化を優先 | MP3 はフレームの global_gain を 1.5 dB 単位で書き換え（mp3gain と同じ方式、再エンコードなし）。FLAC / WAV は可逆なので再エンコード。AAC / Vorbis はスキップ（オプションで再エンコード） | MP3 はバイト単位で無変更 |
| ReplayGain タグだけ | 音声は変えず、全曲に ReplayGain 2.0（基準 −18 LUFS）の track gain / peak を書き込む | 追加のみ |

Opus はどの方法でも、ヘッダの出力ゲイン（Q7.8、1/256 dB 単位）を書き換えます。再エンコードはしません。

### タグの引き継ぎ

- **MP3**: 元ファイル先頭の ID3v2 ブロックと末尾の APEv2 / ID3v1 を **バイト単位でそのまま** 新しい音声の前後に付けます。歌詞（USLT / SYLT）、ジャケット（APIC）、独自フレームも含めて変わりません。
- **FLAC / Ogg Vorbis / M4A / WAV**: lofty で元ファイルのタグ（Vorbis comment と PICTURE、MP4 の ilst と covr、RIFF INFO と ID3 チャンク）を読み、新しいファイルへ書き込みます。

### 安全策

- 上書き時は元ファイルを `対象フォルダ\_loudnorm_backup\` に同じ階層で移します（このフォルダは走査対象外）。
- 「変更した曲だけ別フォルダへ」を選ぶと元ファイルには触れません。
- 上げる方向の補正は、既定で真のピークが −1.0 dBTP を超えないよう抑えます。
- 更新日時は既定で元のまま保ちます。
- 既存の ReplayGain タグがある曲を補正すると、そのタグの値は補正前のままになります（表に注記が出ます）。

## コマンドライン（テスト用）

```
loudnorm --cli <フォルダ> [--method reencode|lossless|tags] [--tol 1.0] [--mp3 cbr320|cbr256|v0] [--out 出力フォルダ] [--jobs N] [--sample-peak] [--fallback] [--apply]
```

`--apply` を付けない限りファイルは変更しません。Windows では GUI アプリとしてビルドされるため起動時にコンソールは開きません。`--cli` のときは起動元のコマンドプロンプトに出力しますが、プロンプトは処理の終了を待たずに戻ります（`start /wait loudnorm.exe --cli ...` で待てます）。
